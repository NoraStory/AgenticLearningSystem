# CodeForge Academy — 最终完整实现计划

## Summary

基于用户提供的 Next.js 16 前端(含 API_SPEC.md / DATABASE_DESIGN.md / AGENT_DESIGN.md),用 **Go 1.26** 实现完整后端。系统包含:PostgreSQL(16张表)+ Redis(4层记忆缓存)+ MinIO(对象存储)+ 6个AI Agent(智能路由+4种协作模式)+ 15个Tool插件(前端可开关)+ DAG工作流编排引擎 + 沙箱自修复(Windows受限令牌)。现有Python检测引擎(checker/tracer,已验证可用)作为Go子进程调用。前端78个计划.md + 65个.rs脚手架作为初始课程数据导入。

## 6个Agent + 智能路由 + 4种协作

### 智能路由 (router_agent)
- 关键词路由:编译错误→code_reviewer+self_heal;面试/算法→problem_tutor+interview_coach;项目→project_mentor;概念原理→learning_assistant+web_search;博客→community_helper
- 用户画像影响:弱点话题自动追加docs_search;初学者追加详细解释
- L4语义去重:相似问题直接返回历史答案

### 6个Agent

| Agent              | 职责                  | 可用Tool                                                     |
| ------------------ | --------------------- | ------------------------------------------------------------ |
| learning_assistant | 概念问答,RAG检索      | course_search, web_search, docs_search, wiki_search, mindmap_gen |
| code_reviewer      | 代码审查,优化建议     | code_execute, code_lint, github_search                       |
| problem_tutor      | 题目讲解,解题引导     | leetcode_fetch, code_execute, progress_query                 |
| project_mentor     | 项目实战指导,架构建议 | code_execute, code_lint, github_search, course_search, mindmap_gen |
| interview_coach    | 面试模拟,出题评分     | leetcode_fetch, code_execute, progress_query, wiki_search    |
| community_helper   | 博客/README/Gist生成  | course_search, mindmap_gen, github_search                    |

### 4种协作模式
- **Sequential**:A→B→C串行接力(概念讲解→代码审查→题目练习)
- **Parallel+Merge**:A||B||C并行,merge合并(多来源检索)
- **Debate**:A→B→A→B多轮辩论收敛(代码质量讨论)
- **Mentor-Apprentice**:mentor出题→用户答→reviewer审查→mentor评估(项目实战)

### 并行互不干涉保障
- 每个Agent独立goroutine + 独立context.Context(独立超时/取消)
- Agent间不共享内存,通过channel传递消息
- Tool调用通过sync.Mutex串行化(避免API限流)
- AI对话历史按`agent:{type}:{user_id}`独立存储在Redis
- 最多3个Agent同时并行

## DAG工作流编排引擎

**7种节点类型**:agent_node, tool_node, router_node, parallel_node, merge_node, condition_node, human_node

**预置工作流**:
1. `code_submit`:提交→编译→(成功?reviewer:自修复)→(修复成功?合并[human确认]:error_coach)
2. `complex_question`:router→并行多Agent→merge→mindmap_gen
3. `interview_mode`:interview_coach出题→用户答→code_reviewer评分→讲解
4. `project_guide`:project_mentor出任务→用户写码→code_reviewer审查→评估

## 4层记忆系统

| 层   | 存储       | TTL  | 内容                             |
| ---- | ---------- | ---- | -------------------------------- |
| L1   | Redis      | 24h  | 当前对话上下文、页面状态         |
| L2   | PostgreSQL | 7d   | 本次会话全部对话、提交记录       |
| L3   | PostgreSQL | 永久 | 用户画像、知识图谱、成就         |
| L4   | pgvector   | 永久 | 问题向量化、相似去重、个性化推荐 |

## 沙箱自修复

- Go用`CreateRestrictedToken()`+`CreateProcessAsUser()`+Job Object创建受限子进程
- 限制:无网络、只写临时目录、CPU 30s、内存 256MB
- **自修复流程**:编译失败→捕获stderr→沙箱内AI分析修复→重新编译→通过则合并(human确认)→不通过则返回错误
