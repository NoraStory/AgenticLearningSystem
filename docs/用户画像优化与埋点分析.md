# 用户画像模块优化 — 实施记录

> 状态：✅ 已实施（2026-08-02）

## Context

画像模块此前图表全手写、BKT 参数硬编码、画像不驱动推荐与 Agent、存在死代码与统计 bug。本方案分 6 阶段全部落地。

## 一、BKT 参数落库（阶段 1）

- 新增 `bkt_params` 表（`BktParam` 模型）：category（唯一，default `global`）/ prior / transition / guess / slip / source（`default`|`fitted`）/ sample_size。
- 种子：5 大类（python/cpp/database/algorithm/agent）+ `global` 兜底，幂等 FirstOrCreate。
- 运行链路：`bktParamsFor(category)`（内存缓存 5 分钟 TTL + category→global→default 三级回退）→ `bktUpdate(p, prior, correct)` 纯函数公式不变。
- **顺带修复两个统计 bug**（与个人中心同类问题）：
  - `updateProfileFromActivity` 完成课程数原统计全站课程（`Where("status = completed")` 无用户过滤）→ 改为按用户 `learning_progresses progress>=100`；
  - 解题数原 `Where("passed = ?")` 字段不存在（Submission 只有 Status）恒为 0 → 改为 `status = 'accepted'`。
- `agentProfile` 的 `computed_level` 原传 0 → 改为真实统计调 `computeLevel`。
- 新增 `knowledge_tracing_test.go`（纯函数）：序列行为 / clamp / 参数敏感性。

## 二、埋点采集（阶段 2）

自建轻量方案（不引入 umami/plausible 等第三方平台——单用户自用系统，数据与画像同库、零新容器）。

- **后端** `POST /api/v1/events`：body `{events:[{name, props}]}`（≤20 条/次），复用 `UserActivity` 表（type=name，props 序列化进 metadata jsonb），游客自动落 Demo 用户。
- **服务端补点**：收藏/取消收藏、点赞、创建笔记、笔试提交、搜索（`trackEvent` 辅助函数）。
- **前端 SDK** `frontend/src/lib/track.ts`：批量（≥5 条或 3s 定时）+ `navigator.sendBeacon`（页面关闭也能送达）+ localStorage 队列离线兜底（上限 200 条防膨胀）。
- **Tracker 组件**挂 layout：`usePathname` 自动上报 `page_view`（首屏也会）。
- **关键交互埋点**：搜索、做题开始（problem_start）、课程浏览（course_view）、笔试开始（interview_start）、简历上传/导出。

## 三、画像驱动打通（阶段 3）

- **弱项推荐** `GET /courses/recommended/weak`：knowledge_states 按 category 平均掌握度 < 45% 为弱项，取该方向未完成课程补强（含推荐理由 reason），无画像数据回退热门榜（保持原结构，首页永不空）。首页已切到新接口。
- **system_prompt 注入**：`buildSystemPromptForUser(imageMode, uid)` 保留热加载+时间注入，追加画像摘要（等级/累计学习/连续打卡/各方向掌握度/待加强 top3，≤8 行，标注数据来源防编造数字）。
- **progress_query 增强**：课程完成 + 学习时长/连续打卡 + 弱项 top3 知识点（带掌握度），提示 LLM 给出复习建议。

## 四、BKT 离线拟合（阶段 4）

- **脚本** `backend/scripts/bkt_fit.py`：纯标准库（Python 3.14 无 pyBKT wheel 且无 gcc），EM 算法（前向-后向，log-sum-exp 防下溢）。
  - 转移矩阵标准 BKT `[[1-T, T], [0, 1]]`（已掌握不忘记）；
  - M 步 transition = Σξ(0→1)/Σγ(0)（从"未掌握"角度估计）；
  - **同分类多技能序列联合拟合**（共享参数，比逐序列独立拟合稳定——独立拟合对 4 维参数严重欠定会退化）；
  - 序列 <3 丢弃、clamp (0.01,0.99)、guess+slip<0.9 退化约束、输出 loglik 供人工判断。
- **Go 集成** `POST /api/v1/admin/bkt/fit`：从 submissions 按 (user, problem) 构建做题序列（注意 recordKnowledgeState 只在 accepted 时调用，原始序列必须从 submissions 建）→ 调脚本 → 写回 bkt_params(source=fitted) → `refreshBktCache()` 立即生效。`GET /api/v1/admin/bkt/params` 排查用。
- 手动触发，不加 cron。合成数据验证：slip/guess/transition 接近真值（±0.08 内）。

## 五、前端图表 + 学习洞察（阶段 5）

- **知识图谱**：ECharts graph 关系图（`components/profile/KnowledgeGraph.tsx`），动态 import + echarts/core 按需注册（只用 GraphChart + Tooltip，懒加载不拖首屏）。节点=真实 knowledge_states（掌握度四档着色、size 按 attempts），边=分类中心节点 + 同分类相邻连线，force 布局可拖拽缩放，tooltip 显示掌握度。
- **雷达图/趋势图**：recharts（已装未用，用起来了）——RadarChart + BarChart。
- **学习洞察** `GET /api/v1/agent/insights`：行为分布（30 天按事件类型）、时段偏好（24 小时学习分布）、兴趣分布（course_view 按 category）、14 天趋势（事件数+时长）、一致性（累计时长/日均/活跃天数/最活跃星期几）。前端 `InsightsCards.tsx` 渲染，空数据显示空态。
- **不回归转圈**：画像页 3 请求改为 4 请求（+insights），独立失败 + 8s 超时逻辑原样保留。
