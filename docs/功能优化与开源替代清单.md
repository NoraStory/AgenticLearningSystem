# CodeForge Academy — 功能优化与开源替代清单

> 承接 `bug-vivid-noodle.md` 的 BUG 审查，本报告聚焦**功能层面的优化点**与**手写轮子 → 成熟开源库/托管服务的替代机会**。所有发现已做源码级复核。仅作报告，不含代码改动。

## Context

系统是 AI 学习平台，后端 Go+Gin+GORM，前端 Next.js 16。审查发现：大量本可用成熟库替代的手写逻辑（SSE 解析、API 客户端、图表、表单、代码沙箱、LLM 客户端、文档导出），以及若干"功能名存实亡"的假数据模块（简历分析、项目分析、导出）。其中最值得关注的是**已安装但从未使用的库**——`recharts`、`react-hook-form`、`zod` 全站 0 处调用，等于装了没用。

## 一、前端 · 高替代价值

### F1. SSE 流式消费两处手写重复，无 AbortController/重连/容错
- **位置**：[agent/chat/page.tsx:280](frontend/src/app/agent/chat/page.tsx#L280)、[interview/page.tsx:168](frontend/src/app/interview/page.tsx#L168)（`getHint`）
- **现状**：两处几乎相同的 `response.body.getReader()` + `while(true)` + 手拆 `data:` 行 + 裸 `JSON.parse`。无 AbortController（离开页面流不停）、无断线重连、单帧解析崩溃会吞掉整条流。
- **OSS 替代**：`@microsoft/fetch-event-source`（支持 POST、自定义 header、自动重连）或 `eventsource-parser`（Vercel，纯解析）。配合 AbortController 一行中止，并消除两份重复逻辑。

### F2. API 客户端无超时/重试/去重，全站手写 useEffect+fetch+useState
- **位置**：[lib/api.ts:17](frontend/src/lib/api.ts#L17)（`apiFetch`）、几乎每个 page.tsx
- **现状**：`apiFetch` 仅处理 token 和 envelope 解包，无超时（`agent/profile/page.tsx:74` 还在用 `Promise.race+setTimeout` 手写超时）、无重试、无请求去重、无缓存。每个页面三件套 `useEffect`+`fetch`+`useState`，切走再回来全量重取。全 `src/` 零 `AbortController`。
- **OSS 替代**：`@tanstack/react-query`（缓存/stale-while-revalidate/去重/乐观更新一把梭）+ 底层可搭 `ky`（超时/重试/hooks）。一次性解决 F1/F2 及多处页面泄漏。

### F3. Markdown 完全不渲染，Agent 回复纯文本
- **位置**：[agent/chat/page.tsx:449](frontend/src/app/agent/chat/page.tsx#L449)
- **现状**：`<div className="whitespace-pre-wrap">{msg.content}</div>`，后端返回的 markdown（标题/列表/表格/代码块）全部丢失格式。对一个 AI 对话产品是体验硬伤。
- **OSS 替代**：`react-markdown` + `remark-gfm`（表格/删除线）+ `rehype-raw`。流式场景直接喂增量字符串即可。

### F4. 代码块无语法高亮
- **位置**：[course/[id]/page.tsx:213](frontend/src/app/course/[id]/page.tsx#L213)
- **现状**：`<pre><code>{section.code}</code></pre>` 纯单色文本，课程代码和 Agent 代码块都无高亮。Monaco 只用于编辑器，展示场景无覆盖。
- **OSS 替代**：`shiki`（VS Code 同款 TextMate，支持增量流式高亮）或 `rehype-pretty-code`（与 react-markdown 集成）。与 F3 天然配套。

### F5. Mermaid 手写正则+手画 SVG，仅支持 flowchart 垂直单列
- **位置**：[agent/chat/page.tsx:54-118](frontend/src/app/agent/chat/page.tsx#L54)
- **现状**：`extractMermaidBlocks` 正则提取 + `parseMermaidFlowchart` 正则解析节点边 + `MermaidPreview` 手画 SVG，只渲染垂直链式流程图。`sequenceDiagram`/`classDiagram`/`pie` 全部退化为 `<pre>` 原文。
- **OSS 替代**：官方 `mermaid` 库 `mermaid.render()` 一行渲染所有图表类型；React 封装用 `react-mermaid` 或 `useEffect` 调 `mermaid.run()`。

## 二、前端 · 中替代价值（"装了没用"重灾区）

### F6. recharts 已安装但全站 0 处使用，图表全手写
- **位置**：[agent/profile/page.tsx:313-377](frontend/src/app/agent/profile/page.tsx#L313)（雷达图/环形进度/热力图/趋势柱状图/进度条）
- **现状**：`recharts` 在 `package.json` 已装、`components/ui/chart.tsx` shadcn 封装也存在，但业务代码 0 处 `from 'recharts'`。所有图表手写 `<svg circle strokeDasharray>` / `<div height:%>`，无 tooltip/动画/交互/响应式。
- **行动**：直接用已装的 `recharts`（`<RadarChart>`/`<BarChart>`/`<LineChart>`/`<Tooltip>`），无需新增依赖。

### F7. "知识图谱"实为卡片网格
- **位置**：[agent/profile/page.tsx:271-299](frontend/src/app/agent/profile/page.tsx#L271)
- **现状**：标题叫"知识掌握图谱"，实为 `topSkills` 排序取前 12 渲染成 `grid-cols-3` 卡片+进度条。无节点、无边、无图结构。
- **OSS 替代**：`reactflow`（React Flow）或 `cytoscape.js`+`react-cytoscapejs` 做交互式知识图谱。

### F8. react-hook-form + zod 已安装但全站 0 处使用
- **位置**：`components/ui/form.tsx`（shadcn 封装存在），表单散落在 `agent/profile`、`resume`、`project`、`course/[id]`、`interview` 等页面
- **现状**：`zod`（含 `drizzle-zod`）已装却未用于表单；`saveEdit` 直接 `JSON.stringify` 发送无校验；全站无客户端校验。
- **行动**：用已装的 `react-hook-form` + `@hookform/resolvers` + `zod` 接管表单状态与校验，无需新增依赖。

### F9. 无全局状态，用户态散落 localStorage
- **位置**：[layout.tsx:13](frontend/src/app/layout.tsx#L13)（无 Provider）、[lib/api.ts:18](frontend/src/lib/api.ts#L18)（token 每次读 localStorage）、[agent/chat/page.tsx:191](frontend/src/app/agent/chat/page.tsx#L191)（session_id 手动存取）
- **现状**：用户信息无全局缓存，每个页面各自请求 `/users/me`；session 管理散落；无 auth 守卫。
- **OSS 替代**：`zustand`（轻量客户端状态）+ react-query（服务端状态）；auth 改用 Next.js middleware + cookie 而非 localStorage token。

## 三、后端 · 高替代价值

### B1. 代码沙箱手写 subprocess + 关键词黑名单，无真正隔离
- **位置**：[sandbox/runner.go:23,176-264](backend/internal/sandbox/runner.go#L23)
- **现状**：13 个字符串黑名单 + `exec.CommandContext` 直接跑宿主机进程，仅 5s 超时和 `cmd.Env` 限制。`MemoryKB` 恒为 0，无内存/CPU 限制，无文件系统/网络/cgroup 隔离。黑名单极易绕过（`__import__('os').system(...)`、`eval`、base64、C++ `system()`、JS `require('child_process')` 都没拦）。
- **OSS 替代**：
  - **Judge0**（自托管判题系统，REST API，60+ 语言，内置 isolate）——可直接替换 `Run`/`ValidateWithCases`。
  - **isolate**（ioi/isolate，Linux cgroup+namespace 轻量沙箱，Go 通过 CLI 调用）。
  - **Docker 方案**：`docker run --rm --network=none --memory=256m --cpus=1` 每次执行，最通用。

### B2. LLM 客户端手写 SSE + 双协议 + 手拼 JSON
- **位置**：[llm/client.go:57-178](backend/internal/llm/client.go#L57)
- **现状**：手拼 `map[string]any` 请求、`bufio.Scanner` 逐行解析 SSE、`responses` 与 `chat_completions` 两套 wire protocol 各 ~50 行结构重复。无重试/退避、无 token 计数、**不支持 function calling**（直接导致 B4 的关键词路由）。`MaxOutputTokens` 硬编码 4096/2048。
- **OSS 替代**：
  - **volcengine/volcengine-go-sdk**：火山引擎官方 SDK，原生对接 Ark（豆包），内置重试/SSE/流式。
  - **openai/openai-go**：OpenAI 官方 Go SDK，Ark API 兼容 OpenAI 协议可直接用，解锁 function calling/vision。
  - **sashabaranov/go-openai**：社区维护最广，支持 streaming/vision/function calling。

### B3. 无限流、无安全头中间件
- **位置**：[server.go:33-36,126-149](backend/internal/api/server.go#L33)
- **现状**：中间件链仅 `Recovery`+`logger`+`cors`。`/code/run` 可被反复触发编译（DoS），`/agent/chat` 可无限消耗 LLM 额度。无 HSTS/X-Frame-Options/nosniff/CSP。`fmtInt`（server.go:155）还手写数字转字符串（本可用 `strconv.Itoa`）。
- **OSS 替代**：`ulule/limiter` 或 `didip/tollbooth`（限流，Redis 后端，项目已依赖 Redis）+ `gin-contrib/secure`（安全头）+ `gin-contrib/cors`（替代手写 CORS）。

### B4. Agent 路由与工具规划纯关键词匹配，未用 function calling
- **位置**：[agent.go:179-195](backend/internal/api/agent.go#L179)（`routeAgent`，6 个 `strings.Contains`）、[tool_planner.go:58-151](backend/internal/api/tool_planner.go#L58)（`planAgentTools`，~20 个 `containsAny` 分支 + 末尾 `llmShouldSearch` 只返回 yes/no）
- **现状**：工具执行全串行，`scheduleTools` 仅按 phase 排序非 DAG 调度。关键词漏召回率高（"我的程序出问题了"不含"报错"就路由不到 code-review），映射硬编码无法泛化，`llmShouldSearch` 不规划具体工具组合。Agent 的"智能"名不副实。
- **OSS 替代**：直接用 OpenAI/Ark 的 **function calling**——把 `toolCatalog` 转成 function schema，让 LLM 自行决定调用序列。或上 **LangChainGo** / 字节 **eino**（原生支持 Ark，内置 agent+tool 编排）。依赖 B2 先完成。

## 四、后端 · 中替代价值

### B5. 简历分析/项目分析返回硬编码假数据
- **位置**：[apps.go:59-113](backend/internal/api/apps.go#L59)（`resumeAnalyze` 固定 `score:78, atsScore:74` + 固定关键词；`resumeOptimize` 的 `optimizedSection` 硬编码"张三|软件工程师"文本）、[apps.go:262-294](backend/internal/api/apps.go#L262)（`projectAnalyze` 固定 4 条建议与代码无关）
- **现状**：上传的 PDF/DOCX 只存了 key 从未解析；评分/关键词/优劣分析全是 mock；项目分析不读源码。用户发现后信任崩塌。
- **OSS 替代**：`ledongthuc/pdf` 或 `unidoc/unipdf`（PDF 文本）+ `nguyenthenguyen/docx`（DOCX），提取后发给已有 `llm.Client.ChatWithImages` 做真实分析。这是功能缺失而非换库。

### B6. PDF/DOCX 导出手写字节拼接，不支持中文
- **位置**：[apps.go:114-187](backend/internal/api/apps.go#L114)（`makePDF` 手拼 `%PDF-1.4` + xref + PostScript 命令；`makeDocx` 手写 OOXML zip）
- **现状**：PDF 只有 Helvetica 西文字体不支持中文；不支持换行/分页；文本超 1500 字截断；DOCX 单段落单 run 无格式。
- **OSS 替代**：`signintech/gopdf` 或 `johnfercher/maroto`（PDF，支持中文字体/分页/表格）+ `nguyenthenguyen/docx` 或 `unidoc/unioffice`（DOCX）。或 `chromedp` 渲染 HTML 转 PDF 质量最高。

### B7. 图片缩放手写最近邻，质量差且慢
- **位置**：[storage/store.go:110-145](backend/internal/storage/store.go#L110)（`optimizeForVision`）
- **现状**：双层 for 循环 `img.At(sx,sy)` 逐像素最近邻，1280×960 约 120 万次虚函数调用，锯齿严重。
- **OSS 替代**：`golang.org/x/image/draw`，`draw.CatmullRom.Scale(...)` 一行替换，质量更高性能更好。

### B8. 联网搜索 curl.exe 兜底，不可移植
- **位置**：[tool_planner.go:740-782](backend/internal/api/tool_planner.go#L740)（`wikiSearch` 的 `:760-766` fallback 到 `exec.CommandContext(ctx,"curl.exe",...)`）
- **现状**：Go HTTP 客户端失败后外壳调 `curl.exe`（Linux 无此文件）。多级回退链 SearXNG→Wikipedia HTTP→Wikipedia curl.exe 增加复杂度，搜索结果无缓存。
- **行动**：诊断 Go TLS 失败根因（代理/证书/`HTTP_PROXY` 环境变量），删除 curl 兜底；以已接入的 SearXNG 为唯一入口。

## 推荐落地顺序

1. **先吃"免费午餐"**（已装未用，零新增依赖）：F6（用 recharts）、F8（用 react-hook-form+zod）。立竿见影，无引入风险。
2. **补前端渲染与数据层**（体验硬伤）：F3（react-markdown）+ F4（shiki）+ F5（mermaid）配套；F1+F2（SSE 库 + react-query）统一数据获取并修资源泄漏。
3. **后端架构升级**（解锁智能）：B2（官方 LLM SDK）→ B4（function calling 替代关键词路由），这是让 Agent 真正"智能"的关键链路。
4. **安全与隔离**（与 bug 报告重叠）：B1（沙箱容器化）、B3（限流+安全头）。
5. **补真实功能**：B5（简历/项目分析接 LLM）、B6（文档导出库）、B7（图片缩放库）、B8（删 curl 兜底）。
